# 14 · Self-review, iteration, and trust

**Source:** Dykes ch. 8, PDF pp. 295–302, tables 8.6–8.7; ch. 9, pp. 304–344; Knaflic chs. 5, 7, and 10. The severity table, tests, and closure criteria are operational adaptations.

## Dykes's workflow: Sketch → Design → Refine

Table 8.7 (pp. 301–302) proposes sketching, designing, and refining. Before using software, sketch visuals for each story point and check flow. Then build them with real data and allow adjustments. Finally assess how each visual supports the story, correcting labels, colors, scale, annotations, and other details. Gather feedback from an outsider if possible.

Agent application:
1. Sketch: define the Big Idea, select scenes and alternatives using the same data. For a simple request, a reasoned choice suffices.
2. Design: produce the requested format and verify correspondence to data and purpose.
3. Refine: review the actual output (not only the plan), correct material defects, recheck. If rendering is unavailable, say so and limit claims to structural review.
4. Close: deliver only when no known critical errors remain and reading is functional. Do not iterate indefinitely in pursuit of cosmetic improvements. If a limitation cannot be resolved, explain it.

## Review order

| Severity | What to look for | Response |
|---|---|---|
| Critical | Incorrect data, invented source, hidden denominator, misleading scale, false causation, omitted adverse evidence | Correct before delivery or declare the conclusion blocked |
| High | Audience cannot interpret comparison, unsupported title, missing context, ambiguous Aha, or unjustified decision | Redesign scene or revise story |
| Medium | Distant legend, excess annotations, inconsistent colors, difficult reading | Simplify, align, and check |
| Low | Minor spacing or style details without effect on understanding | Correct if proportionate to the task |

## Visual and narrative tests

- Gaze test: what is seen first? second? does it match the message?
- Comparison test: can the reader reconstruct the difference from evidence without relying only on the title?
- Title test: read them consecutively; is horizontal logic understandable? On each page, do title, chart, and text support one coherent idea?
- Trust test: zero-baseline bars/areas, proportional time, sizes by area, justified grouping, verified sources, sums, and units. Also review scale and aspect ratio, period selection, spelling, and conventions.
- Accessibility test: legibility at destination, contrast, redundant cues beyond color, alternative text or table when appropriate.
- Audience test: what would someone without prior knowledge understand? What legitimate question would they have? Can they describe the insight unaided? Do they know what is being asked?
- Decision test: distinguish conclusion from recommendation, state conditions and limits, do not fabricate owner or benefit.

If the user requests an audit, specify problem → effect → correction → how to verify. If they request a final product, apply controls internally and communicate only relevant decisions or constraints. Module 05's rubric is diagnostic, not certification. Do not claim external review, rendering, user testing, or installation when they did not occur.

## Refinement example

A chart of rates 49% and 51% uses bars starting at 48%, two saturated colors, and title “B vastly exceeds A.” Correction: zero-baseline bars or dots with explicit scale, title “B exceeds A by 2 percentage points,” and sample sizes if known. Do not claim significance. Review: intact values, proportional reading, bounded title, absence of causation; if bases are missing, note it. Changing colors is insufficient if the axis remains misleading.
