# 16 · Proportional execution protocols and integration guide

**Source:** Dykes ch. 4, PDF pp. 107–109, 130–143; ch. 6, pp. 199–211; ch. 8, pp. 300–302; ch. 9, pp. 304–344; Knaflic chs. 1, 7, 8, and 10. Modes and routes are operational skill design, not the authors' classification.

## Activation by objective

| Mode | Signal | Complementary reading | Minimum delivery |
|---|---|---|---|
| Quick | One chart, title improvement, or scale question | 09 or 12 as needed; checks 05/14 | Result, useful clarification, and relevant limits |
| Exploratory | Data without a story or hypothesis | 07 and 13; 12 if visualizing | Questions, patterns, tentative insights, checks |
| Professional | Specific report of findings | 07, 08, 09, 13; 10/12 depending on visual | Big Idea, evidence, context, interpretation |
| Executive | Communication to time-constrained decision-makers | 08 and 11; 13 and 09 | Data Trailer or initial conclusion, evidence, and decision/question |
| Comprehensive | Complete presentation, report, or dashboard | 07–14 depending on stage; 05 for controls | Storyboard, scenes or dashboard, sources, conclusion, and appendices |
| Audit/redesign | Existing file or chart | 14 and 15, 09/10/12 depending on problems | Prioritized diagnosis, corrections, validation, outstanding items |

Do not automatically read every module. Use the six original modules as core; load only relevant complementary ones. Do not apply Story Zone to block an explicit informational request; choose depth according to value, difficulty, time, and medium. In exploration, do not force an Aha; in information, do not invent an action.

## Integrated execution sequence (adaptation)

1. Objective and audience: Knaflic's who/what/how, Dykes's eight factors if appropriate.
2. Evidence: quality, 4D Framework, exploratory analysis. Form insight and check actionability; if unsupported, deliver exploration or plan.
3. Big Idea and Aha: define a supported central assertion and its consequences. Use Story Zone to decide format.
4. Storyboard: design from the Aha; select setting/hook, rising insights, and subsequent steps. For impatient executives, use Data Trailer. In standalone reading, provide sufficient context.
5. Visualize: right data first, then chart and calibration. Apply decluttering, hierarchy, color, accessibility, titles, and annotations. Use alternative if comparison fails.
6. Build requested artifact using available capabilities. Do not confuse sketch or specification with functional file.
7. Refine: sketch–design–refine; validate data and actual artifact, review horizontal and vertical logic, make material corrections. Deliver with limitations if inspection was not performed or data is missing.

## Resolution criteria between the two sources

- Both prioritize context and clarity. Knaflic governs the six-lesson base structure; Dykes deepens insight selection, narrative, calibration, and change orientation.
- Knaflic permits conclusion at beginning or end; Dykes distinguishes informing (inverted pyramid) from storytelling (arc) and allows Data Trailer. Choose by objective; do not hide insight for suspense.
- Knaflic avoids pie and dual axis by default; Dykes describes cases and alternatives. Maintain preference for simple forms and common baseline, with justified exceptions, never distortion.
- Dykes proposes consequences and action; respect informational/exploratory use and do not invent recommendations. Guided discussion is a valid ending when no solution is available.
- When a visual tactic conflicts with integrity, integrity wins. When a template conflicts with the real task, the real task wins. Do not combine methods as a formality.

## Scope control

This skill communicates data: it does not introduce persuasive marketing, ornamental design, general data engineering, predictive models, or advanced programming. It may use statistical analysis or tools if the task requires them, but must not attribute techniques external to these books or claim the book establishes a specific statistical test. For high-impact decisions, preserve uncertainty and flag specialized validation if needed.

## Additional acceptance tests

| Test case | Required result |
|---|---|
| One figure with context suffices | Clear text, not a 10-page presentation |
| No target exists | Do not invent target KPI; indicate absence |
| Attractive result but biased prior hypothesis | Seek counterevidence, do not build data cameo |
| Two independent observations | Separate stories or group only with explicit relationship |
| Executive wants quick answer | Aha and essential evidence first; option to expand |
| Audience unfamiliar with chart | Orient to axes/variables; reveal if useful |
| Before/after comparison with different bases | Verify denominators; avoid causation |
| Truncated bar chart | Correct scale to zero and title |
| Potential impact without assumptions | Do not invent figure; state condition or investigation |
| No artifact creation capability | Clear specification and explicit limitation, no file promise |

Tests are manual specifications; no behavioral benchmark has been executed in an installed agent.
